# Diary keymaps and persistent settings

The requested result is a separate keymap settings screen, persistent selection
in `~/.ada_tui_diary/config.toml`, and closer Emacs/Helix editing behavior.
Implementation stays in the existing Ada/Malef architecture.

## Design

- Keep the pure controller independent of filesystem/environment access. Add a
  settings save operation to its screen port; the terminal adapter writes config.
- `S` opens settings from the calendar. Arrows, j/k, C-n/C-p or 1/2 select
  Emacs/Helix, Enter saves and applies, Esc cancels. Show binding help for each.
- Preserve M as a session-only quick toggle. Startup priority is CLI, environment,
  config, Emacs. CLI/environment do not overwrite config.
- Use `[editor] keymap = "emacs"` or `"helix"`. Missing config uses defaults;
  malformed/unsupported settings produce a useful error without overwriting the
  file. Save via temporary file plus atomic rename, retaining the original on
  failure. Settings errors keep the screen open and current keymap unchanged.
- Emacs: C-s/C-r incremental literal search, C-x C-s save, C-x k close,
  kill ring with consecutive kill accumulation and M-y rotation, C-x C-x exchange
  point and mark, C-v/M-v page movement. C-d does not alter the kill ring.
- Helix: count prefixes for movement/selection/paste, f/F/t/T across lines,
  r replace, / and ? literal search, n/N repeat, Alt-; flip anchor/head.
  Counts are bounded and cancel on Esc. Existing selection-first operations stay.
- Literal search and a single selection are explicit limits; no regex engine,
  language-server commands, multi-cursor emulation or custom remapping in this change.

Alternative considered: put filesystem writes directly in the controller; rejected
because it would break the existing port boundary. A generic user-remapping engine
would add substantial grammar/conflict handling beyond selecting these two keymaps.

## Execution

1. Extend real PTY tests first: isolated HOME, settings save/cancel/restart and
   override priority; fail against current app.
2. Implement config adapter, settings state/controller/renderer and startup load.
3. Extend PTY tests for Emacs search/kill ring and Helix counts/find/replace/search;
   observe failure, implement controller changes, retain baseline regression tests.
4. Update README/help, format changed Ada sources, run full test and PTY suites,
   and inspect diff/warnings.

Review focus: malformed config preservation; unwritable config; HOME isolation in
tests; Unicode search offsets; count/prefix cancellation; search cancel restoring
selection; CLI/environment override never writes config.

## Verification record

- Implemented all four execution steps; changes remain available in the working tree.
- Added real PTY regressions for settings replacement/cancel/restart/override,
  malformed settings, tabs/comments/single-quoted values, failed atomic save,
  and explicit data directories without HOME.
- Added Emacs regressions for Unicode and adjacent search, backward match bounds,
  cancellation, accumulated kills, kill-ring rotation, and deletion with a mark.
- Added Helix regressions for counted selection/paste, find across Unicode lines,
  replacement, reverse search, prefix cancellation, repeated till motion, and
  the insertion-to-normal cursor transition.
- Independent review identified five defects; all received reproductions and fixes.
- `make test` and `make smoke` passed on macOS ARM64. The Linux native packaging
  case is skipped by the existing release tests on this host.
- App, presentation, and integration Ada sources passed `-gnatwa -gnatwe`
  semantic checks; changed sources were formatted with GNATformat.
