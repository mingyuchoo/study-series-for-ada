# Diary release scripts

**Goal:** Format, lint, build, test, bundle, and create installers from the existing Ada workspace.

**Architecture:** Keep release I/O under `scripts/`. Preserve the current domain/application/package boundaries. Build each platform on that platform; Windows 11 uses the project's existing WSL runtime model.

**Decisions:**

- `release.sh` supports Linux and macOS, produces a portable archive, matching source archive, SHA-256 manifest, and native installers (`.deb` plus `.rpm`, or `.pkg`).
- `release.ps1` runs the same pipeline in a selected WSL distribution and uses Inno Setup to create a Windows installer containing the Linux payload and a PowerShell launcher.
- Native Windows support would require a separate terminal/storage port. A container-only release would add a runtime dependency to every platform. Neither is needed for the existing WSL architecture.
- Version defaults to `alire.toml`; explicit versions and output paths are validated. Tool failures stop the pipeline. Temporary staging is isolated and cleaned; existing output is never recursively deleted.
- Release compilation forces optimization and static Ada/compiler runtimes; runtime dependencies are checked before packaging. Linux still requires a compatible system libc.
- macOS dependency-cache fixes select native terminal constants and the Darwin stdin symbol. The same PTY suite runs on macOS.

## Verification

Run script regression tests, Bash and PowerShell syntax checks, the real Ada formatting/lint/build/unit/storage/PTY pipeline, inspect generated archives and package metadata, verify SHA-256 manifests, and execute the extracted Linux payload with `--help`.

macOS installer execution and Windows installation require their respective hosts and must be reported separately from Linux verification.

## Results

- Nine release regression tests pass, including real Debian/RPM packaging of hyphenated prerelease versions, caller-relative paths, restrictive umask, source manifest pins, and SHA-256 contents.
- PowerShell parsing, Windows argument escaping, process output, failure propagation, and help checks pass under PowerShell 7.7 on Linux.
- Real Linux ARM64 formatting, linting, optimized compilation, Ada unit tests, storage tests, and PTY tests pass; native Debian/RPM artifacts are generated, inspected, extracted, and executed with `--help`.
- The source archive uses a local Malef pin. Alire dependency resolution and pre-build actions succeed using the bundled dependency sources.
- Independent review identified caller-relative output resolution, RPM prerelease normalization, and Windows installer system-directory redirection issues. All were corrected; the first two have regression coverage. Windows installer uses explicit native architecture installation mode.
- Windows release keeps the existing WSL runtime model. Native macOS and Windows execution remain host-specific verification limitations. Installer signing and notarization are outside this task.
